# Record Shelf — Code Audit Report

> **Date:** 2026-05-30 · **Version audited:** 0.8.0
> **Method:** Multi-agent audit on Opus 4.8. 9 finders (security ×2, performance ×2, quality ×2, deploy, features ×2) surfaced 56 candidate issues + 20 feature ideas; an adversarial verifier re-read the actual code behind each finding (rejecting 2, recalibrating several severities); a synthesis pass deduplicated overlapping reports into the entries below.

## Executive Summary

Overall health is **good**: the codebase is well-organized, type-safe at the boundary it controls, and free of any exploitable critical vulnerability or data-loss bug. No findings rose to critical, and only one reached high. The single most important fix is the **KV caching gap for large collections** — collections over 100 items are never cached, so every visit to a real collection re-fetches the entire thing from Discogs, defeating the cache for exactly the data that needs it most. Headline counts: **~40 confirmed findings** (1 high, 12 medium, 18 low, 5 info, plus deploy items) across Security, Performance, Code Quality, and Deployment, with **2 candidate findings rejected** during verification. Most issues are hardening and maintainability improvements rather than active bugs; the deployment story has a few reproducibility/secret-hygiene gaps worth closing before leaning on the Docker path.

## Security

**Discogs token cookie set without `Secure` flag** — `[medium]` · `src/lib/stores/settings.ts:15-26`
The 365-day token cookie sets `SameSite=Strict` and `path=/` but omits `Secure`, so a single plaintext-HTTP request (stray `http://` link, redirect, or a MITM hop in the Docker/Caddy path) can exfiltrate a long-lived read credential. **Fix:** append `;Secure` (gate on `location.protocol === 'https:'` for localhost dev); ideally set the cookie server-side as `HttpOnly+Secure+SameSite=Strict`.

**Token stored in both localStorage and a JS-readable cookie** — `[medium]` · `src/lib/stores/settings.ts:48-91`
The credential lives in two of the most XSS-harvestable locations; a `document.cookie`-set cookie can never be `HttpOnly`. No injection sink exists today, so this is blast-radius reduction. **Fix:** pick one storage location — prefer a server-set `HttpOnly` cookie and drop the localStorage copy (keep only a non-sensitive `hasToken` flag). Note the value endpoint accepts an `x-discogs-token` header the client never sends, so the client genuinely doesn't need to read the token.

**No Content-Security-Policy** — `[medium]` · `src/app.html:10-19`
There is no CSP anywhere (no `kit.csp`, no `hooks.server.ts`, no `_headers`), and an unhashed inline theme script in `app.html` would otherwise force `'unsafe-inline'`. With credentials in JS-readable storage, CSP is the highest-leverage defense against a future injection bug. **Fix:** add `kit.csp` in **hash mode** (correct for Cloudflare per-isolate constraints) so the inline script is auto-hashed; directives `script-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`.

**No security response headers** *(spans deploy + security lenses)* — `[medium]` · `svelte.config.js:7-18`
No `X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, `HSTS`, or `Referrer-Policy` on either adapter. **Fix:** add `static/_headers` for Cloudflare Pages and a `hooks.server.ts` `handle()` (plus Caddy HSTS) for adapter-node — note `kit.csp` only emits CSP, not the other headers, so a `_headers`/hooks layer is still required.

**`/api/value` uses server token with no client auth (request amplification)** — `[medium]` · `src/routes/api/value/[username]/+server.ts:75-128`
When `DISCOGS_TOKEN` is set server-side, any unauthenticated client can POST up to 50 release IDs and drive token-backed Discogs calls; on Cloudflare the per-isolate `rateLimitChain` does **not** serialize concurrent requests across isolates, making token-budget exhaustion *easier* than the in-memory limiter implies. **Fix:** gate the env-token fallback behind the same cookie check used by `/api/collection`; don't rely on the per-isolate limiter for abuse protection.

**Unvalidated/unencoded `username` injected into Discogs URLs** — `[medium]` · `src/lib/api/discogs.ts:83, 92, 112, 145`
The route param flows raw into four token-bearing API paths with no validation or `encodeURIComponent`. Host is fixed (`api.discogs.com`) so this is **not** arbitrary-host SSRF or token exfiltration, but reserved chars (`?`, `#`, `%2e%2e`) can corrupt the query or redirect to other same-token endpoints. **Fix:** add a `src/params/username.ts` matcher (`/^[A-Za-z0-9_.-]{1,50}$/`) plus `encodeURIComponent` — closes all four call sites globally.

**CSV export does not neutralize spreadsheet formula injection** — `[medium]` · `src/lib/components/CollectionExport.svelte:25-51`
`escapeCsv()` does RFC-4180 quoting only; a Discogs-controlled field like `=HYPERLINK(...)` becomes a live formula in Excel/Sheets. User-action-gated (modern apps prompt), hence medium. **Fix:** prefix any cell starting with `= + - @ \t \r` with a single quote before quoting, applied to all stringified fields.

**`releaseIds` elements not validated as integers** — `[low]` · `src/routes/api/value/[username]/+server.ts:67-101`
Only `Array.isArray` + length is checked; elements are interpolated into the marketplace path. No exfiltration (fixed host, blind GET, response not reflected). **Fix:** `releaseIds.map(Number).filter(n => Number.isInteger(n) && n > 0).slice(0,50)`, reject if empty.

**`/api/widget` unauthenticated, hardcoded user, per-isolate cache** — `[low]` · `src/routes/api/widget/+server.ts:7-71`
Public data, but zero self-rate-limiting plus a per-isolate cache means frequent cache misses amplify server-token use. **Fix:** back with KV cache; make username env-configurable; add cache/CORS headers.

**Upstream Discogs `statusText` forwarded to clients** — `[low]` · `src/lib/api/discogs.ts:73`
Unmapped errors throw `API error: ${statusText}` and propagate the upstream status code as the app's own. Reason phrase only (no token/trace leak); the real issue is coupling app error semantics to Discogs. **Fix:** map unknown upstream errors to a generic message + normalized 502/500; log the real `statusText` server-side.

**Settings page navigates to unvalidated `?redirect`** — `[low]` · `src/routes/settings/+page.svelte:14, 17-30`
`goto(redirectTo)` with a raw query value. Not a current open redirect (SvelteKit `goto` is same-origin), but fragile against `//evil.com` and future `location.href` refactors. **Fix:** require a single leading `/`, reject `//`.

**Compare redirect builds unencoded usernames** — `[info]` · `src/routes/compare/[user1]/[user2]/+page.server.ts:15`
Inconsistent with sibling loaders that `encodeURIComponent`. Same-origin, trusted `/settings` destination; reserved chars can't appear in Discogs usernames. Code-consistency nit. **Fix:** wrap the embedded path in `encodeURIComponent`.

**Token cookie is non-HttpOnly + inaccurate privacy copy** — `[info]` · `src/lib/stores/settings.ts:15-26`
Inherent to client-managed-token design; localStorage already exposes the token, so the cookie adds little marginal XSS risk. The concrete actionable item is the **inaccurate copy** at `settings/+page.svelte:99, 207-209` claiming the token is "never sent to our servers" — the cookie *is* sent on every request. **Fix:** correct the privacy copy; optionally move to a server-set `HttpOnly` cookie.

## Performance & Efficiency

**Collections over 100 items are never written to KV cache** — `[high]` · `src/routes/u/[username]/+page.server.ts:35-43`
The page load fetches only page 1, then guards the cache write with `items.length >= totalDiscogsItems`, which is always false for collections > 100 items. So KV only ever holds small collections; every visit to a real (large) collection misses cache and re-fetches profile + all pages from Discogs. The 1hr TTL benefits exactly the wrong collections. *(A large collection can incidentally land in KV via the `/compare` path, but not via normal browsing.)* **Fix:** persist the full collection after progressive loading completes (a finalize endpoint, or a server-side `waitUntil` fetch+cache — the more robust option on Cloudflare).

**`computeCollectionStats` + ~13 derived consumers recompute the whole array on every page append (O(n²) loading)** *(spans perf-frontend + perf-network lenses)* — `[medium]` · `src/routes/u/[username]/+page.svelte:58, 66-96, 432-593`
Each progressive append spreads `items` into a new array, re-deriving stats (two full passes in `discogs.ts:176` and `:290`) plus ~13 child components from scratch. For a 3000-item collection that's ~30 recomputes over a growing array. Mitigated in practice: appends are network-gated (~1/sec) and 5 heavy consumers are `LazySection`-gated, so it's per-append jank, not a freeze. **Fix:** batch appends (assign `items` every N pages / on rAF), make stats incremental, and collapse the two passes in `computeCollectionStats` into one loop.

**Value-estimator in-memory price cache and rate limiter are per-isolate** *(spans security + perf lenses)* — `[medium]` · `src/routes/api/value/[username]/+server.ts:18-61`
`priceCache` and `rateLimitChain` are module-scope; on Cloudflare they're per-isolate and non-persistent, so the "survives across requests" comment (line 18) is misleading and cross-isolate rate limiting is unenforceable. Also note this endpoint's `rateLimitedFetch` has **no 429 retry** (unlike the collection client) — a 429 just yields a null price. **Fix:** move price caching to KV (`price:<releaseId>` with TTL); accept that the limiter is best-effort.

**Progressive client loader has no server-side pacing; silent truncation on 429** — `[medium]` · `src/routes/u/[username]/+page.svelte:75-92`
`fetchCollectionPage` has no 1100ms delay (unlike `fetchUserCollection`), and a page-level 429 makes the loop `break` silently, leaving stats computed on partial data with the progress bar stuck. *(Server-side `fetchDiscogs` does retry 429s 3× with backoff, absorbing transient limits — hence medium.)* **Fix:** surface a retryable error state instead of silently breaking; optionally add bounded client concurrency with pacing.

**`randomHighlights` re-shuffles a full array copy on every append** — `[medium]` · `src/routes/u/[username]/+page.svelte:242-251`
`shuffleArray(items).slice(0, 12)` allocates and Fisher-Yates-shuffles the whole collection on each of ~30 appends to keep 12 items. CPU cost is negligible; the real harm is redundant cover-image downloads and a jarring reshuffle/flicker of the Highlights grid each append. **Fix:** sample 12 random indices (O(12)), or compute once after load completes.

**`CollectionBrowser` re-filters/sorts the whole array and re-derives facets on every change** — `[medium]` · `src/lib/components/CollectionBrowser.svelte:61-122, 176-180`
`filteredItems` runs `filter` (with per-item `toLowerCase`/`join`) + `sort` over the entire array on every keystroke and append; `genres`/`formats`/`decades` (61-67) re-scan the whole array though `stats` already has these breakdowns. Bounded by 300ms debounce and pagination, so it's a scalability improvement, not a hang. **Fix:** precompute a lowercased search blob per item; derive facet lists from the existing `stats.*Breakdown`; consider virtualizing the grid.

**API responses set no `Cache-Control` headers** — `[low]` · `src/routes/api/collection/[username]/+server.ts:28-66`
Responses are cookie-authed, so Cloudflare's edge won't cache them by default and `public` caching would be a data-leak hazard — the only safe, real benefit is **browser-side `private` caching** on quick re-navigation. *(No `/api/compare` endpoint exists; the full-collection branch is already KV-backed.)* **Fix:** add `cache-control: private, max-age=…` only; do not use `public`/edge caching.

**KV cache hard-expires with no stale-while-revalidate** — `[low]` · `src/lib/server/cache.ts:26-39`
First request after expiry must synchronously re-fetch. Impact is smaller than feared: the `/u/[username]` cold path only fetches page 1 + profile (~2s); the genuinely slow synchronous full re-fetch is the `/compare` path and the no-page-param `/api/collection` branch. Single-user app, so no "storm." **Fix:** soft-expiry + `platform.context.waitUntil(refreshAndWrite)`, paired with a longer KV `expirationTtl` so the stale entry still physically exists when read.

**Widget in-memory cache is per-isolate** — `[low]` · `src/routes/api/widget/+server.ts:10-15`
The 5-min module-scope cache rarely hits on multi-isolate Cloudflare, so most polls issue two upstream Discogs calls. (Works correctly on the single-process Docker path.) **Fix:** back with KV (`widget:pottejd`, 5min TTL).

**Value estimator over-fetches and re-samples, defeating its own cache** — `[low]` · `src/routes/api/value/[username]/+server.ts:99-121`
The real issue: `ValueEstimate.svelte:18-19` randomly re-samples each click, so cached IDs differ run-to-run; combined with serial 1100ms pacing, a cold 50-item estimate takes ~55s. **Fix:** use a stable sample, KV-back the price cache, optionally shrink the sample (results are extrapolated anyway).

**`LazyImage` has no IntersectionObserver despite its name** — `[low]` · `src/lib/components/LazyImage.svelte:17-32`
Only sets native `loading="lazy"`; every image mounts an `<img>` immediately. Most call sites are bounded/windowed (RecordCard slices to 24, CoverGrid to 12); the only unbounded usage is the wantlist page (`wantlist/+page.svelte:100`). **Fix:** rename to reflect it's a native-lazy wrapper, or add an IntersectionObserver (with `rootMargin`) matching `LazySection`.

**`CoverGrid` `{#each}` has no key** — `[low]` · `src/lib/components/CoverGrid.svelte:13-26`
Unkeyed reconciliation patches every `<a>`/`LazyImage` in place when the (reshuffled) array changes, forcing image re-decode; inconsistent with `CollectionBrowser` which keys by `id`. Capped at 12 items. **Fix:** `{#each items as item (item.basic_information.id)}` — but full benefit requires stabilizing `randomHighlights` (companion finding).

**`YearHeatmap` re-filters `allYears` per decade row** — `[low]` · `src/lib/components/YearHeatmap.svelte:9-19, 23-27`
`getYearsInDecade` filters the full year range per row, per append. A few hundred integer comparisons — negligible next to `computeCollectionStats`. **Fix:** precompute a single `$derived` `Map<decade, year[]>` and iterate that. Opportunistic only.

**`CollectingCalendar` builds Date + `toLocaleDateString` per cell in the render loop** — `[low]` · `src/lib/components/CollectingCalendar.svelte:85-92, 124-128`
~371 cells each run an Intl format on every reactive pass (LazySection-gated, so only after scroll-in). **Fix:** precompute title strings into the `DayData` objects in `generateCalendarData`; reuse one `Intl.DateTimeFormat` instance.

## Code Quality & Architecture

**Per-release fetch errors silently treated as $0** — `[medium]` · `src/routes/api/value/[username]/+server.ts:99-131`
401/429/network failures all collapse to `{lowestPrice: null}`, indistinguishable from "no marketplace data." If a token loses marketplace permission, the user sees a confidently-wrong $0 estimate. *(UI does show "0 of N items," and a fully-missing token is hard-rejected, tempering it.)* **Fix:** distinguish hard failures — throw 401 on auth failure, stop on repeated 429; at minimum return a failed-request count so the client can warn "estimate incomplete."

**401 (invalid token) not mapped to a clear error** — `[medium]` · `src/lib/api/discogs.ts:54-73`
404/403/429 are handled but 401 falls through to `API error: Unauthorized` with `code: undefined`; loaders never redirect to `/settings` for a present-but-invalid token. *(Tokens are validated at save time, so this only hits on later revocation/expiry.)* **Fix:** add `if (status === 401) throw new DiscogsAPIError('Invalid or expired Discogs token', 401, 'BAD_TOKEN')` and handle `BAD_TOKEN` in loaders (redirect to `/settings`).

**Compare loader maps every unexpected error to 404** — `[medium]` · `src/routes/compare/[user1]/[user2]/+page.server.ts:178-192`
The fallthrough `throw error(404, e.message)` turns network/parse failures into a misleading "Not Found" and leaks raw `e.message`. *(403/429 are `DiscogsAPIError` and handled correctly; only genuinely non-Discogs errors hit this.)* **Fix:** use `error(500, 'An unexpected error occurred')`, log the original server-side, matching `u/[username]/+page.server.ts:69`.

**Profile route is a ~970-line monolith** — `[medium]` · `src/routes/u/[username]/+page.svelte:1-970`
Conflates progressive loading, cache orchestration, domain computation (badges 261-325, shuffle 242-249, 7 filter fns 171-221), and ~25 presentation sections. No runtime impact, but the pure functions with branching business rules can't be unit-tested inside a `.svelte` script. *(~327 lines are CSS; much of the rest is thin template.)* **Fix:** extract `calculateBadges` → `src/lib/utils/badges.ts`, `shuffleArray` → `src/lib/utils/array.ts`, the keyboard handler → a `use:keyboardNav` action; collapse the 7 filter fns into one `openDrawer` + predicate builders.

**Artist-name disambiguation regex `/\s*\(\d+\)$/` copy-pasted across 13 sites** — `[medium]` · `src/lib/api/discogs.ts:225` (+ 12 others)
The same transform is hand-rolled everywhere (ArtistLoyalty, CollectionExport, CoverGrid, RecordCard, widget, compare, …); behavior is already drifting (some add `.toLowerCase().trim()`). No `formatArtists`/`cleanArtistName` helper exists. **Fix:** create `src/lib/utils/discogs.ts` exporting `cleanArtistName()` / `formatArtists()` and replace all call sites.

**Brand gradients/palette hardcoded ~22× (hex trio in 24 files) despite existing CSS vars** — `[medium]` · `src/routes/u/[username]/+page.svelte:728-750, 854, 933`
`app.css` defines `--gradient-primary`/`--color-primary` etc., but literal `linear-gradient(135deg, #6366f1, #8b5cf6)` and the brand hex trio are duplicated throughout. The dark-theme override of `--color-primary` (`#818cf8`) never reaches the literal-hex surfaces, so dark mode silently diverges. **Fix:** replace literals with `--gradient-*`/`var(--color-primary)`; have `BarChart`/`DonutChart` reference a shared palette constant.

**Nav-bar logo SVG + footer markup/CSS duplicated across routes** — `[medium]` · `src/routes/u/[username]/+page.svelte:346-355, 631-633`
The logo SVG (3 nav-bars), `.home-link` CSS, and the "Not affiliated with Discogs" footer (4 files) are repeated verbatim. **Fix:** extract `<SiteNav />` and `<SiteFooter />` into `src/lib/components/`, ideally hoisted into `src/routes/+layout.svelte`.

**`fetchDiscogs` casts unvalidated JSON to `T`** — `[low]` · `src/lib/api/discogs.ts:34-52`
No runtime shape check; a malformed 200 (HTML via proxy, schema change, empty body) flows into pagination math. *(No crash in practice — callers catch and degrade to a generic 500; only downside is a non-specific error.)* **Fix:** `try/catch` around `json()`, plus a minimal `Array.isArray(releases)` / pagination-object guard surfacing a clear `DiscogsAPIError`.

**POST `/api/value` reads `request.json()` with no parse guard** — `[low]` · `src/routes/api/value/[username]/+server.ts:67-72`
A malformed body throws a `SyntaxError` → raw 500 instead of 400; `releaseIds` elements untyped. No injection (fixed host) and garbage keys only poison the attacker's own cache entries. **Fix:** `try/catch` → `error(400)`; filter to `Number.isInteger(id) && id > 0`. *(Overlaps the releaseIds security finding — same remediation.)*

**`getAlbumKey` / artist `flatMap` assume `artists` exists** — `[low]` · `src/routes/compare/[user1]/[user2]/+page.server.ts:66-72, 126-127`
Line 126 does `.artists.map(...)` with no `|| []` guard (unlike `discogs.ts:224`); an undefined `artists` throws a TypeError (then mis-reported as 404). Rare — Discogs reliably includes ≥1 artist. *(Line 71's `artists[0]?.name` already handles the empty-array case.)* **Fix:** guard `.artists` with `?? []` and use `artists[0]?.name?.toLowerCase?.()`. Same unguarded access at `u/[username]/+page.svelte:204`.

**Progressive loader trusts `pageData.pagination` shape** — `[low]` · `src/routes/u/[username]/+page.svelte:79-90`
Untyped `pageData` + bare `catch { break }` means a contract-violating 200 silently stops loading with no warning. *(The `!items?.length` guard and Discogs' empty trailing pages backstop the claimed "infinite loop" — at most a couple extra requests.)* **Fix:** validate `pagination` fields are finite, add an upper bound, surface a non-fatal warning instead of silently breaking.

**`test-token` returns `data.username` off untyped `any`** — `[low]` · `src/routes/api/test-token/+server.ts:27-28`
No `typeof === 'string'` check; consumed only cosmetically ("Connected as: …"), so worst case is "Connected as: undefined." **Fix:** type the response, guard for string, return 502 on unexpected body.

**`medianYear` is the upper-middle element, not a true median** — `[low]` · `src/lib/api/discogs.ts:257-261`
`sortedYears[Math.floor(len/2)]` picks the upper of two middle values for even lengths. **Fix:** average the two central elements on even lengths; sort a copy (`[...years]`) to avoid mutating the intermediate.

**`readCache` casts KV JSON with no shape validation** — `[low]` · `src/lib/server/cache.ts:27-32`
`cached as CachedCollection` is trusted; a cross-deploy schema change could yield a partial object. Bounded by the 1hr TTL and trusted write path. **Fix:** add a schema-version field (treat mismatches as a miss); at minimum verify `cachedData?.data?.items` and `expiresAt` exist.

**Repeated `Object.entries(stats.X).map().sort().slice()` chart wiring** — `[low]` · `src/routes/u/[username]/+page.svelte:223-239`
`decadeData`/`genreData`/`formatData`/`styleData` are four near-identical `$derived` blocks (decadeData sorts ascending by label, the rest by value desc). **Fix:** `toChartData(record, { labelFn?, sort, limit? })` in `src/lib/utils/chart.ts`; pull the `8`/`12` limits into named constants. *(A 5th related shape in `CollectionDNA.svelte:30` has a different output and won't cleanly share the helper.)*

**Magic thresholds/strings scattered in component scripts** — `[low]` · `src/routes/compare/[user1]/[user2]/+page.svelte:11-16`
Similarity buckets (30/15/5), badge thresholds (1000/500/100/25, ratios 0.8/0.5/0.4), and slice limits (12/20/30) are inline literals; `constants.ts` holds none of them. **Fix:** centralize as `SIMILARITY_BUCKETS`, `BADGE_SIZE_THRESHOLDS`, `TOP_LIST_LIMIT`, etc.; have the extracted badge util read them.

**`src/lib/index.ts` is an empty placeholder** — `[info]` · `src/lib/index.ts:1`
SvelteKit's scaffold default; the lib is otherwise well-organized into subdirs. **Fix:** delete the placeholder, or expose new `$lib/utils` via a curated barrel (not components — tree-shaking).

**`computeCollectionStats` computes `medianYear` that no UI consumes** — `[info]` · `src/lib/api/discogs.ts:257-261, 321`
Dead output: computed, cached, tested, but never rendered (only `averageYear` is shown). **Fix:** surface it in the UI (arguably more useful than the mean for skewed collections) or remove it from `CollectionStats`, the computation, and the cache shape.

## Deployment & Build

**Local `.env` (Discogs token) can be baked into the Docker build layer** — `[medium]` · `.dockerignore:1-4`
`.dockerignore` excludes only `node_modules`/`build`/`.svelte-kit`/`.git`; `COPY . .` (`Dockerfile:6`) copies any `.env` into the build stage. Multi-stage build means it doesn't reach the final image, only the discarded intermediate layer, and no `.env` exists in the repo today — so it's latent defense-in-depth, not an active leak. **Fix:** add `.env`, `.env.*` (`!.env.example`), plus `coverage`/`test-results`/`.wrangler`/`docs`/`static/*.pdf`; inject `DISCOGS_TOKEN` at runtime via `docker run -e`.

**Build-time `npm i @sveltejs/adapter-node` is unpinned and unrecorded** — `[medium]` · `Dockerfile:4-5`
`npm ci` (reproducible) is immediately followed by `npm i @sveltejs/adapter-node`, which installs a floating latest version absent from `package.json`/lockfile — defeating `npm ci`'s integrity and making Docker builds non-reproducible. *(Secondary deploy path, build-time only.)* **Fix:** add `@sveltejs/adapter-node` to `devDependencies` (pinned), regenerate the lockfile, and drop the ad-hoc `npm i`.

**Two divergent svelte.config files; Docker silently overwrites** — `[low]` · `svelte.config.docker.js:1-18`
`Dockerfile:7` copies the docker config over the real one; any future kit-level setting must be duplicated or the node build diverges, and CI never exercises the node path. *(Today the only divergence is the necessarily-adapter-specific `routes` vs `out` — the real value is preventing future drift.)* **Fix:** collapse to one config selecting the adapter via env (`process.env.ADAPTER === 'node'`); add a CI job that runs the node build.

**CI has no dependency audit or security scanning** — `[low]` · `.github/workflows/ci.yml:9-78`
Five jobs, none run `npm audit`, dependency-review, or CodeQL; no Dependabot. **Fix:** add `npm audit --audit-level=high` (or `actions/dependency-review-action` on PRs) and enable Dependabot/CodeQL. Note: manifest-based audits won't catch the unpinned `adapter-node` — pinning it (above) is the real fix for the Docker surface.

**Stale wrangler `compatibility_date` (2024-12-01)** — `[low]` · `wrangler.toml:3-4`
Pinned far behind wrangler `^4.61` and Jan-2026 workers-types; safe (retains old defaults) but misses newer runtime semantics. **Fix:** bump to ~2026-01 after a smoke test; keep current with deploy cadence.

**No fail-fast env validation for `DISCOGS_TOKEN`/`ORIGIN`** — `[low]` · `src/routes/api/widget/+server.ts:17-26`
Misconfiguration surfaces only as degraded runtime behavior. *(Lazy per-request env reads via `$env/dynamic/private` are correct/required for Cloudflare — the gap is only the Docker startup path.)* **Fix:** add an adapter-node startup check in `hooks.server.ts` (assert a real https `ORIGIN`, warn if token absent); document `ORIGIN`/`PORT` in `.env.example`.

**Coverage thresholds set to 40% (weak gate)** — `[info]` · `vite.config.ts:12-17`
Actual coverage (~60%) sits well above the gate, so it provides little regression protection; several `+page.server.ts` loaders are at 0%. **Fix:** staged ratchet (e.g. 55% now → add server-route tests → raise further) plus per-directory thresholds for `src/routes/api`.

## Feature Roadmap

### Quick Wins (trivial / small)

- **Most Valuable Records (per-item value heatmap)** — surface the per-release prices the value endpoint *already returns and discards*; rank top-20 + a value-concentration stat. Touches `ValueEstimate.svelte`, `src/routes/api/value/[username]/+server.ts`, `CoverGrid`/`RecordCard`.
- **Duplicate & Variant Detector** — group by `master_id` / normalized artist+title to flag exact dupes and "same album, different pressing." Pure client-side over `items`. New `DuplicateDetector.svelte`, reusing `CollectionDrawer`/`CoverGrid`.

## Recommended Order of Attack

1. **Cache large collections in KV** (`high`, `+page.server.ts:35-43`) — the one fix with broad perf + rate-limit payoff; use server-side `waitUntil` to cache the full collection.
2. **Append `;Secure` to the token cookie** (`medium`, trivial, `settings.ts:15-26`) — one-line credential-exposure fix.
3. **Neutralize CSV formula injection** (`medium`, small, `CollectionExport.svelte:25-51`).
4. **Validate & encode `username`** (`medium`, small, `discogs.ts` + new `src/params/username.ts`) — one matcher closes four call sites.
5. **Gate `/api/value` env-token fallback + add `Number.isInteger` validation** (`medium`+`low`) — stops token-backed amplification and hardens input in one pass.
6. **Map 401 → `BAD_TOKEN` and fix the compare 404 fallthrough** (`medium`×2) — turns cryptic errors into actionable UX.
7. **Add CSP (hash mode) + security headers** (`medium`) — highest-leverage XSS hardening given JS-readable credentials.
8. **Pin `adapter-node` + extend `.dockerignore`** (`medium`×2) — make the Docker path reproducible and secret-safe.
9. **Stabilize `randomHighlights` + key `CoverGrid` + batch progressive appends** (`medium`) — kills the visible reshuffle flicker and the O(n²) recompute together.
10. **Quick feature win: Most Valuable Records** — exposes per-item data already fetched and discarded.
11. **Extract shared utils** (`cleanArtistName`/`formatArtists`, `badges.ts`, `array.ts`, `toChartData`) — pays down the largest maintainability debt and unlocks unit tests.

## Rejected During Verification

Of 56 candidate findings surfaced across the review lenses, **2 were rejected** during adversarial verification:

- **"Hardcoded `ORIGIN=http://localhost` breaks adapter-node CSRF"** — SvelteKit's origin check doesn't block the JSON `Content-Type` requests these endpoints actually use, so the claimed breakage doesn't occur.
- **"Lighthouse runs `vite preview` against a degraded Cloudflare build"** — `vite preview` is adapter-agnostic SSR and is already exercised by the passing e2e job.

Several other findings had their severities adjusted downward during verification and are reported above at the calibrated levels.
